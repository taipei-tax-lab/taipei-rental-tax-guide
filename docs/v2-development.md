# V2 開發與驗收紀錄

日期：2026-09-08。分支：`codex/rental-guide-v2`。基準：`main` 的 `35d9ab7`。

## 使用者確認範圍

充分但不造成混淆的資訊，網站能獨立完成主要查詢。小幫手留在右下方，維持介面與協助定位。參考原稅捐處專區，在新分支開發；CX 新題庫與設定另案處理。使用者後續授權提交並推送開發分支，合併與部署仍另行處理。

## 資訊架構

首頁：屋主／房客 → 情境與優惠摘要 → 不確定時最多三題 → 常見問題 → 官方窗口。

第二層：方案條件、三大稅目、下一步與官方入口，流程／文件和注意事項可展開。完整比較使用相同方案資料，手機改為直向閱讀。

四步 Wizard、獨立流程區、大型試算區與首頁大量資源卡不再重複出現。原有十項房客服務仍可從三類入口取得，沒有丟棄特定身分補貼或權益窗口。

## 技術驗證

- V2 兩個前端 JS 通過語法檢查。
- 8 項單元／建置測試通過，包括建置一致性、靜態錨點、稅目完整性、小幫手片段、15 條導引路徑（最多三題）、不確定答案及更改前答。
- Edge／Playwright：四方案點選與返回、優惠及下一步、文件展開、導引上一題與結果、十個房客入口、深層連結及重新整理通過。
- 320、390、768、1024、1440px 核心頁面無水平溢出；另檢查200%字級。
- 阻斷外部聊天資源，仍可開啟方案及下一步；停用 JS 時仍有四方案與十二個稅目內容。
- 截圖檢視桌機首頁、方案與比較，以及手機首頁與方案。產物在 `.preview/`，不進入版控。
- `site.css`、`messenger.css`、`messenger-ui.js` 及角色素材相對 main 無差異。Messenger 原片段抽離到來源檔；移除的是無關的舊頁面增強腳本引用。

最初沙箱瀏覽器無法載入 Google 靜態資源（ERR_NETWORK_ACCESS_DENIED）；允許唯讀外部載入後，小幫手在320、390、1440px均通過開關及視窗邊界檢查。切換方案時也確認保留同一個 Messenger 實例。未送出 CX 問題，未修改 Google Cloud。

## 使用者驗收：仍待實測

以下為目標，不是已完成的真人測試結果。

| 目標 | 本次可驗證部分 | 待真人驗證 |
| --- | --- | --- |
| 10～20 秒找到摘要或入口 | 首頁直接呈現情境與優惠 | 首次使用者查找時間 |
| 1～2 次點選看到優惠與下一步 | 屋主一點進詳情；房客切換後一點展開服務 | 是否讀懂所選方向 |
| 最多三題並獲得建議理由 | 15 條分支全部通過 | 題目是否符合民眾語言 |
| 不開聊天也能完成查詢 | 聊天失效與無 JS 檢查 | 不同族群實際完成率 |
| 手機不需反覆縮放、關窗或尋找 | 多尺寸、無水平溢出、主流程非彈窗 | iOS／Android 實機、觸控及鍵盤 |
| 看完能說出下一步 | 明確辦理動作與官方連結 | 請使用者自行描述下一步 |

建議情境：房客有補貼的屋主、一般出租屋主、想委託管理的屋主、申請補貼的房客、尚未決定出租方式的屋主。請首次使用者自行操作，記錄第一個點選、耗時、誤入位置及最後描述。
