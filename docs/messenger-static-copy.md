# Messenger 靜態提示文案

這份文件集中管理聊天視窗第一次開啟時適合顯示的固定內容。實際訊息應在 Dialogflow CX 設定，不由前端直接插入 Messenger 內部訊息列表。

## 建議的第一則訊息

```text
您好，我是出租房屋租稅小幫手，可以協助您查詢臺北市出租房屋相關租稅優惠與房客服務。

您可以詢問：
・租金補貼
・出租房屋租稅優惠
・申請資格與辦理流程
・包租代管與租屋權益

本服務提供一般性資訊；實際資格、適用條件及最新規定，仍以主管機關公告與個案審查結果為準。
請勿輸入身分證字號、完整地址、電話或其他敏感個人資料。

例如可以輸入：「我想查中央租金補貼的申請資格。」
```

## 建議的快速問題

若要提供按鈕或建議問題，可規劃以下文字：

- 我想查租金補貼
- 我想了解租稅優惠
- 我想查申請流程
- 我是房客，想查租屋服務

按鈕是否採用、以及對應哪個 intent 或 route，請在 Dialogflow CX 內依目前 Agent 設計決定。

## 前端現有提示

前端 Messenger 已保留兩種元件層級提示：

- 輸入框提示：`請輸入您的問題，例如：公益出租人有何租稅優惠？`
- 回覆等待文字：`小幫手整理資訊中…`

這兩項屬於 Messenger HTML 屬性；第一則歡迎訊息則應由 CX 的 Start Page／Entry fulfillment 提供。

## Dialogflow CX 設定步驟

1. 開啟目前使用的「出租房屋租稅優惠測試」Agent。
2. 進入目前對外使用的 Flow，開啟 Start Page。
3. 在 Entry fulfillment 的 agent response 加入上方第一則訊息。
4. 如需快速問題，依 Agent 現有訊息格式加入建議選項，並建立對應 intent／route。
5. 使用 CX Simulator 測試首次進入、重複進入、無法理解及個資提醒情境。
6. 確認後再以網站 Messenger 測試，避免只在 Simulator 中確認。

## 文案原則

- 固定提示控制在一個畫面可讀的長度，詳細規定交給官方連結或後續追問。
- 不承諾個案一定符合資格，也不把一般資訊寫成正式稅務認定。
- 等待文字只表示系統正在處理，不應暗示已經完成查詢或取得官方核准。
