# Messenger 視窗介面規格

## 目的

讓 Dialogflow CX Messenger 在尚未開始對話時，不只呈現大面積空白，而是先提供清楚、安靜且不干擾輸入的視覺導覽。

這份規格描述的是網站前端介面，不是 Dialogflow CX 的 Start Page、Entry fulfillment 或第一句自動訊息。

## 目前行為

聊天視窗開啟且尚未送出任何查詢時，會在訊息區下方顯示空白狀態提示卡，內容包含：

- 「想先了解哪一項租屋資訊？」主標題。
- 四個可直接送出查詢的主題：租金補貼、租稅優惠、申請流程、房客權益。
- 一般性資訊與個人資料提醒。

使用者自行輸入問題、點選任一主題，或 Messenger 開始送出／回傳訊息後，提示卡會隱藏，完整空間留給正式對話。

## 介面層次

1. 標題列：沿用 Dialogflow CX Messenger 的標題與副標題，使用深 teal 形成識別區。
2. 空白狀態卡：使用淡色漸層、圖示及主題標籤建立開始對話的視覺焦點。
3. 正式訊息：保留 Messenger 原生訊息清單，僅透過官方 CSS 變數調整色彩、間距與圓角。
4. 輸入區：保留在視窗底部，並由響應式尺寸計算避免提示卡遮住輸入框。

## 響應式規則

- 桌機版提示卡限制在 366px 以內，與聊天視窗右側對齊。
- 窄螢幕會縮小內距、圖示及文字，主題改為兩欄。
- 380px 以下改為單欄主題，避免文字擠壓。
- Messenger 視窗寬高仍由 `messenger-ui.js` 依視窗尺寸動態計算。

## 維護位置

- `assets/css/messenger.css`：Messenger 主題與空白狀態卡樣式。
- `assets/js/messenger-ui.js`：Messenger 尺寸、開關狀態、提示卡生命週期及主題查詢。
- `index.html`：Messenger 元件與靜態提示卡的語意結構。

## Dialogflow CX 邊界

網站只在使用者點選主題時呼叫 Messenger 的 `sendQuery`，不會在聊天視窗開啟時自動送出訊息，也不需要修改目前 Agent 的開場設定。
