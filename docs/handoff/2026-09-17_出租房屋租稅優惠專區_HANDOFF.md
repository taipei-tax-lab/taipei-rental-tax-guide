## 4. 架構

本專案為靜態網站架構，所有主要頁面由建置腳本統一編譯輸出：

- `site/content.json`：單一政策資料來源（四方案文案、稅目、適用條件、辦理順序、注意事項、外部連結、房客服務與常見問答）。
- `site/template.html`：全站 HTML 骨架模板，包含佔位符（Placeholders）。
- `scripts/build.mjs`：建置腳本，負責讀取資料、組裝 HTML、計算資源雜湊並產出 `index.html`。
- `assets/css/guide-v2.css`：V2 / Refinement 全站樣式表（含卡片 subgrid、雙方案比較、響應式斷點）。
- `assets/js/guide-rules.js`：快速判斷決策樹規則引擎（純邏輯，不依賴 DOM）。
- `assets/js/guide-ui.js`：使用者互動控制（快速判斷問答渲染、推薦卡片組裝、雙方案切換、桌機 inline-plan 展開）。
- `site/messenger.html`、`assets/css/messenger.css`、`assets/js/messenger-ui.js`：Dialogflow CX 小幫手元件、樣式與視窗適應邏輯。
- `index.html`：建置輸出產物，禁止直接手動修改，任何變更均須透過 `scripts/build.mjs` 重建。

## 7. 最近修復的 Regression（歷程）

- **現象**：快速判斷走到推薦結果時，`guide-ui.js` 會嘗試以 `document.querySelector('#plan-' + id + ' .v2-full-condition').textContent` 取得主要適用條件組裝「仍須確認：……」文案。0915 改版將 conditions 改為列表後移除了該 class，導致執行時期出現 `null.textContent` 例外。
- **修復（Commit `948e64e`）**：在 `scripts/build.mjs` 中，於 `plan.conditions` 的第一個項目保留 `class="v2-full-condition"`。
- **成果**：無須改動 `guide-ui.js`，畫面樣式無任何副作用，推薦流程能精準讀取首要條件文字，並已於 `tests/build.test.mjs` 納入迴歸測試防線。

## 8. Typography / line wrapping regression（正式修復與 Production 驗證）

本項目修復正式上線後於真實瀏覽器排版審查時發現的斷行與文字包裹問題，現已正式發布並通過 Production 驗證：

- **問題原因**：
  1. `.v2-other-taxes span { display:block; }` 選擇器範圍過廣，誤命中內層由 `keepUnits()` 產生的 `<span class="v2-unit">`，導致一般出租卡的「10‰」與「55‰」等數字單位各自被轉為獨立 block，在空間充裕時被拆成「地價稅：一般用地稅率」、「10‰」、「至」、「55‰」多行。
  2. `.v2-site :is(..., .v2-plan-name) { text-wrap: balance; }` 的平衡斷行演算法在中文排版下，對短方案名稱（如「個人租賃住宅包租代管（法人不適用）」）造成提前強迫換行，破壞了「能放滿目前行就放滿、空間不足才自然折行」之原則。
- **修正方式**：
  1. 將選擇器範圍限縮為 direct child：`.v2-other-taxes > span { display:block; }`，並於 `.v2-unit` 明確指定 `display: inline; white-space: nowrap;`，確保「地價稅」與「綜合所得稅」維持分行 block，而內部數字單位保持 inline。
  2. 將全站短標題、按鈕、方案名稱的 `text-wrap: balance` 改為 `text-wrap: wrap` 自然換行，移除提前平衡換行行為；遵循「放不下才自然斷，不粗暴使用全域 nowrap」之原則。
- **Regression Test 防線**：
  1. 單元測試（`tests/build.test.mjs`）：加入 CSS 靜態規則驗證，防範 `.v2-other-taxes span` 誤用與 `.v2-plan-name` 誤加 balance。
  2. 整合測試（`scripts/browser-check.cjs`）：加入 `.v2-other-taxes .v2-unit` computed display 為 `inline` 及 `.v2-plan-name` computed textWrap 不為 `balance` 之檢查。
  3. 跨裝置端到端測試（Playwright Chrome）：涵蓋 Desktop 1440/1280/1024、Tablet 768、Mobile 390 及 100%/125%/150% 縮放，全數通過且 horizontal overflow = 0、pageerror = 0、console.error = 0。
- **上線與驗證狀態**：已於 PR #4（Merge commit `a7a4da8f05da181fd5b50f71fa57b6f7edd0b721`）正式合入 `main`，GitHub Pages 自動部署成功（狀態 `built`），且經真實 Chrome 瀏覽器 Production Smoke Test 100% 通過。

## 12. Favicon 與 Messenger Layout UI 修正（2026-09-17 本輪交付）

本輪針對正式站與測試站審查提出的三項前端 UI / Messenger 問題進行專項修復，完全未觸動政策資料（`content.json`）及 Dialogflow CX 後端設定：

### 1. Browser Favicon 換用臺北市稅捐稽徵處官方 Mark
- **問題**：原 `favicon.svg` 為四個藍色方塊之 generic icon，無法展現官方機關識別。
- **作法**：從既有品牌資產 `assets/images/tpctax-logo.png` 左側乾淨裁切出官方獨立 mark（TRTS 藍金雙色環徽），輸出為 128×128 透明背景專用圖檔 `assets/images/tpctax-mark.png`，保留原比例、不拉伸、不改色、不含「臺北市稅捐稽徵處」中文字樣，確保在 16px/32px browser tab 下仍清晰可辨。
- **模板與建置**：`site/template.html` 替換為 `<link rel="icon" href="./assets/images/tpctax-mark.png" type="image/png">`，經 `build.mjs` 重建同步更新 `index.html`；header 仍維持使用完整 `tpctax-logo.png`。

### 2. Messenger 中間使用提醒（Notice）永遠完整顯示
- **問題根因**：原 `.rental-input-extras` 宣告 `flex: 0 1 auto; min-height: 0; max-height: 35%; overflow-y: auto;`，當對話內容增多或視窗高度較矮時，整區會被 flex-shrink 壓縮產生獨立捲軸；且 `updateInputExtras` 在 compact viewport（height < 400px）會將 notice 移入 `<details>` 折疊。
- **修正作法**：
  1. `.rental-input-extras` 改為 `flex: none; box-sizing: border-box; overflow: visible;`，其內部 `p` 宣告 `flex: none; overflow: visible;`，成為固定不可被壓縮的常駐區塊。
  2. 移除將 notice 移入 `<details>` 的程式碼，提醒文字永遠置於 `<details>` 外部，維持兩行完整顯示。
  3. 若使用者展開「熱門問題」，僅限制 `.messenger-topic-list` 本身之 `max-height: 180px; overflow-y: auto;`（矮視窗 120px），不干擾提醒文字。
- **驗證**：在各 Viewport / Zoom 矩陣、矮視窗、以及 synthetic DOM 負載壓力測試下，`notice.scrollHeight <= notice.clientHeight + 1` 均成立，提醒常駐於 details 外且無文字裁切、無自身 scrollbar。

### 3. Assistant Panel 與 Chat Window 零縫隙接合
- **問題根因**：原程式以 `elements.assistantPanel.style.right = (window.innerWidth - rect.left - overlap) + 'px'` 定位，但在 Windows Chrome / Edge 下，當主頁面有內容垂直捲軸時，`window.innerWidth` 包含系統捲軸寬度（17px），而 `position: fixed` 的 right 是相對於 `clientWidth`（不含捲軸），導致 panel 右側與 chat 左側產生剛好 16～17px 的懸空縫隙；此外，chat 打開時具有 300ms 的 CSS transition，單一 frame 的 RAF 無法捕捉穩定後的 chatRect。
- **修正作法**：
  1. `.assistant-panel` 明確加入 `box-sizing: border-box;`。
  2. 定位改採直接 viewport `left` 基準：`panel.style.left = (rect.left - panelWidth + overlap) + 'px'`、`panel.style.right = 'auto'`、`panel.style.top = rect.top + 'px'`、`panel.style.bottom = 'auto'`、`panel.style.height = rect.height + 'px'`，徹底消除捲軸寬度造成的差值。
  3. `openChat` 觸發時加入雙重 RAF 及 150ms / 350ms 檢查點，並掛載 `ResizeObserver` 與 `transitionend` 監聽。
- **驗證**：在 1440×900、1280×800、1024×768 及 100%、125%、150% 縮放實測中，`abs(gap) <= 1px`、`top difference <= 1px`、`bottom difference <= 1px` 均 100% 達成，外側維持 22px 圓角、接合處平直無雙框線與中間陰影縫。
